# Data Model: Block-Based Trip Planner (Core)

**Feature**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

All ids are UUIDs generated by the client (so optimistic inserts need no round trip). All
synced rows carry `updated_at` (server-set) for last-write-wins (research R5). `position` fields
are fractional-index strings (research R4) and are not unique; ordering is by `position`, then
`id`, so two devices inserting at the same spot never conflict.

## Profile

One per user (`auth.users`). Created on sign-up by trigger.

| Field | Type | Rules |
|---|---|---|
| id | uuid | = `auth.users.id`, PK |
| deletion_requested_at | timestamptz, null | Set by "Delete account"; cleared on sign-in (FR-018a) |

State: `active` (null) → `pending deletion` (set) → back to `active` on sign-in, or purged after
30 days (user and all owned rows deleted by cascade).

## Trip

| Field | Type | Rules |
|---|---|---|
| id | uuid | PK |
| owner_id | uuid | FK → auth.users, on delete cascade |
| name | text | Required, 1–100 chars after trim |
| start_date | date | Required |
| end_date | date | Required, ≥ start_date; max 60 days span |
| deleted_at | timestamptz, null | Set on delete; trip hidden from the list while set |
| created_at, updated_at | timestamptz | Server-set |

State: `active` (deleted_at null) → `deleted` (set; shown under "Recently deleted", restorable)
→ back to `active` on restore, or purged 30 days after `deleted_at` (cascade removes all rows).

On create: insert the 7 default blocks (FR-005).
On date-range shrink: delete placements and day_settings whose `date` falls outside the new
range, after the user confirms (FR-003). Extending needs no row changes (days are derived).

## Day (derived, not stored)

`date` for each day from `start_date` to `end_date` inclusive. Label = date + weekday.

## DaySetting

Optional per-day arrival/departure (FR-006a). Row exists only when at least one is set.

| Field | Type | Rules |
|---|---|---|
| trip_id | uuid | FK → trips, cascade |
| date | date | Within trip range; PK (trip_id, date) |
| arrival_block_id | uuid, null | FK → blocks, on delete set null |
| departure_block_id | uuid, null | FK → blocks, on delete set null |
| updated_at | timestamptz | |

Rule: if both set, arrival block's position ≤ departure block's position (validated in core).
Greyed cells on that day: blocks ordered before arrival or after departure. Display only —
placements in greyed cells are kept and editable.

## Block (Time Block)

| Field | Type | Rules |
|---|---|---|
| id | uuid | PK |
| trip_id | uuid | FK → trips, cascade |
| name | text | Required, 1–40 chars; duplicates allowed |
| position | text | Fractional index; ties ordered by `id` |
| updated_at | timestamptz | |

Rules: a trip always has ≥ 1 block (delete of last block rejected in core and by DB trigger).
Deleting a block deletes its placements (after confirmation) and clears any DaySetting that
referenced it (user is told).

## Item (activity & food list)

| Field | Type | Rules |
|---|---|---|
| id | uuid | PK |
| trip_id | uuid | FK → trips, cascade |
| name | text | Required, 1–200 chars |
| type | enum `activity` \| `food` | Required |
| notes | text, null | ≤ 5,000 chars |
| link | text, null | Must be an http(s) URL if present |
| created_at, updated_at | timestamptz | |

Derived: `placedCount` = number of placements with `source_item_id = id` (FR-010).
Deleting or editing an item never changes placements (FR-009).

## Placement

An event in a cell (FR-007, FR-012).

| Field | Type | Rules |
|---|---|---|
| id | uuid | PK |
| trip_id | uuid | FK → trips, cascade |
| date | date | Within trip range |
| block_id | uuid | FK → blocks, cascade |
| position | text | Fractional index; order within (date, block_id) |
| name | text | Required, 1–200 chars |
| type | enum `activity` \| `food` | Typed placements default to `activity` |
| notes | text, null | ≤ 5,000 chars |
| link | text, null | http(s) URL if present |
| source_item_id | uuid, null | FK → items, on delete set null. Set only when copied from the list |
| updated_at | timestamptz | |

Creation paths:
- **Typed**: name from input, type `activity`, `source_item_id` null.
- **From list** (drag or choosing a suggestion, FR-007a): copies name/type/notes/link from the
  item at that moment and sets `source_item_id`.

## Relationships

```text
auth.users 1─1 Profile
auth.users 1─* Trip
Trip 1─* Block
Trip 1─* Item
Trip 1─* DaySetting ─? Block (arrival), ─? Block (departure)
Trip 1─* Placement *─1 Block
Placement *─? Item (source_item_id, informational only)
```

## Access rules

Every table: a row is readable and writable only if its trip's `owner_id = auth.uid()`
(row-level security; [contracts/database.md](./contracts/database.md)).
